## 1. 한 줄 요약

| | 샘플링 기반 플래닝 | 궤적 최적화 |
|---|---|---|
| 한 줄 | "무작위로 점을 뽑아 **갈 수 있는 길**을 찾는다" | "이미 있는 경로를 **기울기로 다듬어 좋은 길**로 만든다" |
| 잘하는 것 | 해가 있는지 **찾기**(전역) | 부드럽고 제약을 지키는 해로 **개선하기**(국소) |
| 못하는 것 | 매끄러움, 속도·가속도 같은 연속 곡선 제약 | 좋은 시작점이 없으면 엉뚱한 곳에 갇힘 |

실무에서 두 방법은 경쟁보다 **분업**에 가깝습니다. 샘플링이 해의 대략적인 위치를 찾고, 최적화가 그것을 다듬습니다(4.2절, 5.2절).

## 2. 샘플링 기반 플래닝 자세히

### 2.1 세 부품 (일반 지식)

샘플링 기반 플래너는 같은 세 부품으로 이루어집니다.

| 부품 | 하는 일 | 예 |
|---|---|---|
| **샘플러** | 설정 공간에서 후보 자세를 뽑음 | 균등 무작위, 가우시안, 장애물 근처 편향 |
| **유효성(충돌) 검사기** | 이 자세 또는 이 선분이 충돌 없는지 "예/아니오"로만 답함 | 로봇 모델과 장면의 충돌 질의 |
| **연결 규칙** | 두 자세를 어떻게 이을지 정함 | 관절 공간 직선, 한 걸음(steer) |

OMPL은 이 중 **충돌 검사와 시각화를 일부러 넣지 않았습니다**(원문). 어떤 충돌 검사기든 붙여 쓰도록 하려는 설계입니다. 플래너는 충돌 검사기를 **블랙박스**로 부릅니다. 이것이 샘플링 기반의 가장 큰 특징이고, 아래 비교의 많은 부분이 여기서 나옵니다.

### 2.2 계열 (원문: OMPL 플래너 목록)

| 계열 | 대표 | 한 줄 |
|---|---|---|
| 단일 질의 트리 | RRT, **RRT-Connect**, EST, KPIECE | 시작(과 목표)에서 트리를 키워 한 문제를 풂 |
| 다중 질의 로드맵 | PRM, LazyPRM, SPARS | 로드맵을 한 번 만들어 여러 질의에 재사용 |
| 점근적 최적 | RRT*, PRM*, Informed RRT*, **BIT***, FMT* | 샘플이 늘수록 최적 경로로 수렴 |
| 비용 인지 | T-RRT 계열 | 비용 지형이 있을 때 낮은 곳으로 확장 |
| 동역학 고려(control-based) | kinodynamic RRT, SST, KPIECE | 상태를 전파해 동역학 제약을 다룸 |

OMPL의 SimpleSetup은 기하 문제의 기본값으로 (투영이 있으면) KPIECE 계열을, 아니면 RRT-Connect를 고른다고 합니다(원문). RRT-Connect가 "일단 해를 빨리 찾는" 기본 선택이라는 뜻입니다.

### 2.3 성질 (일반 지식 + 원문)

| 성질 | 내용 |
|---|---|
| 확률적 완전성 | 해가 있으면 샘플이 늘수록 찾을 확률이 1로 감. **시간 안에 찾는다는 보장은 아님**. 좁은 통로에서는 매우 오래 걸림 |
| 최적성 | RRT, RRT-Connect, PRM은 최적이 아님. RRT*, PRM*, BIT* 등이 점근적 최적(OMPL 표기) |
| 비결정성 | 시드마다 결과가 다름. 같은 문제를 두 번 풀면 다른 경로가 나옴 |
| 비용 구조 | 시간의 대부분이 **충돌 검사**. 그래서 검사기가 빨라지면 플래너도 크게 빨라짐(5.3절) |
| 후처리 필요 | 경로가 울퉁불퉁하고 연속 곡선 제약이 없으므로 shortcutting, 스플라인 평활화가 뒤따름 |

## 3. 궤적 최적화 (복습)

경로를 매개변수(예: B-스플라인 제어점)로 놓고, 비용을 줄이면서 제약(시작·목표, 속도, 충돌 거리)을 만족하는 매개변수를 **기울기 기반 솔버**로 찾습니다([15](15_bspline_and_augmented_lagrangian.md)). 비용과 제약을 풍부하게 쓸 수 있고 빠르지만, 비볼록 문제라 **초기값 근처의 국소해**를 찾습니다([16](16_motion_planning_concepts.md) 3절).

## 4. 구체적으로 어떻게 다른가

### 4.1 다른 점 표

| 관점 | 샘플링 기반 | 궤적 최적화 |
|---|---|---|
| 푸는 대상 | 설정 공간의 **점과 선분** 그래프·트리 | 곡선의 **매개변수**(제어점 등) |
| 충돌을 아는 방식 | 예/아니오 **호출** (불연속, 미분 불필요) | **거리·기울기**를 제약으로 사용 (매끄러워야 유리) |
| 초기값 | 필요 없음 | **중요함**(국소해) |
| 전역성 | 확률적 완전성 | 국소 최적 |
| 최적성 | 변형(RRT* 등)에서만 점근적 | 국소 최적(비용에 대해) |
| 연속 곡선 제약(속도·가속도) | 약함. 후처리로 보완 | **강함**. 제약으로 직접 |
| 비용·제약의 풍부함 | 제한적(최적 변형은 비용 하나) | 풍부함 |
| 고차원 | 샘플 수가 크게 늘 수 있음 | 상대적으로 잘 확장됨(원문) |
| 실패의 모습 | 시간 초과(못 찾음) | 엉뚱한 해에 수렴 또는 실행 불가 |
| 결과의 재현성 | 시드마다 다름 | 같은 초기값이면 같음 |
| 장애물 모델 | 아무 모양이든 검사만 되면 됨 | 매끄러운 거리 함수가 있어야 좋음 |

이 한 장으로 읽을 점입니다.

- **샘플링은 초기값이 필요 없고 안 풀리면 시간이 더 필요할 뿐**입니다. 최적화는 **시작이 나쁘면 풀렸다고 해놓고 틀린 답**을 줍니다.
- 3.00짜리 "해"는 **충돌 제약을 웨이포인트에만 걸었기 때문에** 생겼습니다([15](15_bspline_and_augmented_lagrangian.md) 2.7절). 웨이포인트 간격(0.0375)이 벽 폭(0.2)보다 작아도, 솔버가 웨이포인트 두 개를 벽 양옆에 두고 **그 사이를 한 번에 건너뛰는** 편이 비용이 거의 안 늘어서입니다. **실행 전에 선분 단위로 다시 검사해야 하는 이유**입니다.
- 최적화 결과는 틈의 모서리를 스치며 지나갑니다. 충돌 제약에 **여유(마진)** 를 두지 않으면 실제로 닿습니다. 이 실험에서는 2 cm를 줬고 웨이포인트를 80개로 늘려야 선분 검사를 통과했습니다(16개와 40개에서는 모서리를 파고듦).
- 시간은 최적화가 더 오래 걸린 경우도 있습니다(RRT 경로에서 시작한 최적화 1.3 s). 이 작은 문제에서는 속도 비교가 의미가 없고, **어떤 일을 하느냐**가 다릅니다.

### 4.3 왜 이런 차이가 나나 (해석)

두 방법이 충돌 검사에서 얻는 **정보의 양**이 다릅니다.

- 샘플링: "이 점은 충돌" 또는 "충돌 아님"이라는 **1비트**만 씁니다. 정보는 적지만, 충돌 모델이 어떻게 생겼든(불연속, 미분 불가, 메시) 동작합니다. 대신 **좋은 방향을 모르고** 널리 뿌려 봐야 합니다.
- 최적화: 거리와 그 **기울기**까지 씁니다. 정보가 많아 **빠르게 수렴**하고 연속 제약을 직접 다룹니다. 대신 기울기가 가리키는 **가까운 골짜기**에서 못 나옵니다.

그래서 "넓게 찾기"는 샘플링이, "정확히 다듬기"는 최적화가 맡는 분업이 자연스럽습니다.

## 5. 각각 언제 많이 쓰나

### 5.1 선택 표 (일반 지식, OMPL 설명 반영)

| 상황 | 먼저 쓰는 것 | 이유 |
|---|---|---|
| 처음 보는 환경, 좁은 통로, 클러터 | 샘플링 (RRT-Connect 등) | 초기값 없이 전역 탐색 |
| 해가 있는지만 빨리 알고 싶음 | 샘플링 | 확률적 완전성, 해를 찾는 것에 특화 |
| 충돌 모델이 불연속·미분 불가 | 샘플링 | 기울기가 필요 없음 |
| 부드러운 궤적, 속도·가속도·토크 한계가 중요 | 최적화 | 제약으로 직접 표현 |
| 시간 최적 또는 에너지 최소 같은 비용이 있음 | 최적화 | 비용 함수가 풍부함 |
| 같은 환경에서 매 주기 다시 계획(MPC) | 최적화 | 이전 해를 초기값으로(warm start) |
| 샘플링이 찾은 해를 개선 | 최적화 + 후처리 | 4.2절 |
| 이동 로봇, 자동차형, 드론 | 샘플링 (동역학 고려 변형) | OMPL이 이 시스템들에 쓰였다고 소개 |

### 5.2 현장의 조합 (원문 + 일반 지식)

- OMPL은 MoveIt의 **기본 플래닝 라이브러리**이고 ROS에서는 MoveIt을 통해 쓰라고 권합니다(원문). 즉 팔 조작의 "이동" 계획은 샘플링 기반이 기본값인 곳이 많습니다.
- 이어서 경로를 **시간 매개변수화·평활화**합니다([16](16_motion_planning_concepts.md) 7절의 TOPP 등). 샘플링으로 해를 찾고 최적화적 후처리로 다듬는 순서가 표준 흐름입니다(일반 지식).

```mermaid
flowchart LR
    A["시작·목표"] --> B["샘플링 플래너<br/>(RRT-Connect)"]
    B --> C["shortcutting<br/>경로 단축"]
    C --> D["궤적 최적화<br/>(B-스플라인, 제약)"]
    D --> E["시간 매개변수화<br/>(TOPP)"]
    E --> F["실행 전 선분·밀집 충돌 재검사"]
```

### 5.3 둘 다 빨라지는 중 (논문 초록)

| 연구 | 주장 (초록) | 방향 |
|---|---|---|
| VAMP (Thomason 외, 2309.14545) | 샘플링 플래너를 세밀한 병렬화로 **500배 이상** 빠르게 해, 계획 시간이 **마이크로초** 수준 | 샘플링이 제어 주기에 들어옴 |
| cuRobo (Sundaralingam 외, 2310.17274) | **병렬 시드**로 GPU에서 궤적 최적화를 풀어 평균 50 ms, 기존 최적화 방법보다 60배 빠름. 병렬 기하 플래너(20 ms)와 충돌 없는 IK(초당 7000 질의 이상)도 포함 | 최적화도 "시드를 많이 뿌려서" 국소해를 피함 |

두 연구의 공통점은 **병렬화로 "많이 뿌리기"를 싸게 만든 것**입니다. 최적화(cuRobo)도 결국 여러 초기값을 샘플링한다는 점에서 두 계열의 경계가 흐려지고 있습니다.

## 6. 신경망 기반 제어 흐름에서

### 6.1 세 갈래

| 갈래 | 아이디어 | 예 (논문 초록 기준) |
|---|---|---|
| **A. 학습된 정책이 플래너를 대신** | 관측에서 곧바로 동작(궤적 조각)을 생성 | Diffusion Policy(2303.04137), Motion Policy Networks(2210.12209) |
| **B. 학습이 고전 플래너를 가속** | 좋은 샘플·시드·휴리스틱을 학습해 플래너에 줌 | MPNet(1907.06013), CoMPNetX(2010.08707), SIMPNet(2408.12831), DiffusionSeeder(2410.16727) |
| **C. 고전 플래너가 빨라져 제어 주기로** | 병렬화로 실시간화 | VAMP, cuRobo (5.3절) |

각 연구가 초록에서 주장하는 내용입니다.

- **Diffusion Policy**: 시각운동 정책을 **조건부 확산(denoising) 과정**으로 표현합니다. 다봉(multimodal) 동작 분포를 잘 다루고, **후퇴 지평(receding horizon) 제어**를 포함하며, 추론 때 점수 함수의 기울기를 따라 **반복적으로 최적화**한다고 설명합니다.
- **Motion Policy Networks (MπNets)**: 깊이 카메라 관측 하나에서 충돌 없는 부드러운 동작을 만드는 end-to-end 모델입니다. **3백만 개 이상의 모션 플래닝 문제, 50만 개 환경**에서 시뮬레이션으로 학습했고, 전역 플래너보다 빠르고 동적 장면에 반응적이며 실제 로봇으로 옮겨진다고 합니다. (학습용 정답 경로를 어떻게 만들었는지는 초록에 없어 확인하지 않았습니다.)
- **MPNet**: 점군에서 환경을 인코딩해 경로를 생성하는 **신경 플래너**입니다. 고전 샘플링 플래너와 **합치는 하이브리드**로 하면 **최악의 경우 이론적 보장**을 유지할 수 있다고 합니다.
- **CoMPNetX**: 신경망이 **구속 조건을 만족하는 자세들을 생성**해 기존 샘플링 플래너를 "터보 충전"합니다.
- **SIMPNet**: 샘플링 플래너의 균등·수작업 샘플링을 **학습된 샘플링 휴리스틱**(그래프 신경망)으로 대체합니다.
- **DiffusionSeeder**: 최적화(cuRobo)는 장애물이 많은 환경에서 모든 시드가 국소해에 갇힐 수 있고, 시드를 그래프 기반 플래너로 얻으면 느려집니다. 그래서 **확산 모델이 깊이 영상에서 다봉 궤적을 생성해 최적화의 시드**로 씁니다. 평균 12배 빨라졌고 부분 관측 시뮬레이션에서 성공률이 10% 높았다고 합니다.

### 6.2 "그대로는 아니더라도" 이어지는 아이디어

| 고전 기법의 아이디어 | 신경망 시대의 모습 |
|---|---|
| 샘플링: **많이 뽑아 고르기** | 확산 모델이 **다양한 후보(다봉 분포)** 를 생성(Diffusion Policy, DiffusionSeeder). 학습된 샘플러가 균등 샘플링을 대체(SIMPNet) |
| 샘플링 + 평가: 롤아웃 후 가중 평균 | **MPPI**: 제어 열을 샘플해 비용으로 평가·가중하는 **샘플링 기반 MPC**. 기울기 없이 동작하고 **미분 불가 비용**을 다루며, 신경망이 학습한 동역학 모델과도 함께 쓰임(논문 초록 2603.29499) |
| 궤적 최적화: **반복적 개선** | 확산의 **역과정(denoising)** 이 점수 함수 기울기를 따르는 반복 최적화(Diffusion Policy 초록). Diffuser는 궤적을 반복 denoise해 **"모델에서 샘플링하는 것과 계획하는 것이 거의 같아지게"** 함(2205.09991) |
| 궤적 최적화: **비용과 제약** | Diffuser가 **분류기 안내 샘플링**을 계획 전략으로 재해석(초록). 비용·제약을 샘플링 과정에 넣는 방식 |
| 최적화: 매 주기 **다시 계획(MPC)** | Diffusion Policy의 후퇴 지평 제어, 동작을 **한 덩어리(chunk)** 로 내고 일부만 실행하고 다시 예측 |
| 계획 문제를 많이 풀어서 **데이터로** | MπNets가 수백만 계획 문제로 학습. MimicGen은 **소수의 사람 시연(약 200개)에서 5만 개 이상의 시연을 자동 합성**(2310.17596) |

### 6.3 정리: 플래너는 사라진 것이 아니라 역할이 바뀐다 (해석)

초록들을 모아 보면 고전 방법은 **세 가지 자리**에 남아 있습니다.

1. **데이터와 시드를 만드는 쪽**: 학습용 문제·해를 만들거나, 최적화의 초기값을 줍니다.
2. **보장과 후처리를 맡는 쪽**: MPNet이 말한 "고전 플래너와의 하이브리드로 보장 유지", 실행 전 충돌 재검사.
3. **제어 주기 안의 안전 필터**: 정책이 낸 동작을 제약 안으로 투영(예: [07](07_fk_and_ik.md) 5.4절의 미분 IK QP로 속도·관절 한계 지키기).

반대로 신경망이 대신하는 쪽은 **초기 추정과 다봉 후보 생성**, 그리고 **관측에서 곧바로 동작으로** 가는 부분입니다. "탐색을 학습으로 대체하고 정확성은 최적화·검사로 보장한다"는 분업이 공통 흐름으로 보입니다(해석, 개별 논문이 이렇게 요약한 것은 아님).

### 6.4 이 프로젝트에 적용하면 (→ 해석)

`AGENTS.md`의 요약으로는 이 프로젝트의 `robot_manipulation/`은 사전학습 인코더가 학습되는 **action-expert**에 입력을 주는 구조입니다. 코드는 이 문서를 쓰며 열어 보지 않았으므로 아래는 개념적 연결입니다.

| 연결 | 내용 |
|---|---|
| 동작 chunk | action-expert가 여러 스텝의 동작을 한 번에 낸다면, 이는 "궤적 한 덩어리"를 출력하는 것이고 매개변수화(스플라인 등)와 제약(속도·관절 한계)이 실행 전에 필요해짐([15](15_bspline_and_augmented_lagrangian.md)) |
| 안전 필터 | 정책의 출력을 미분 IK QP로 한계 안에 투영([07](07_fk_and_ik.md) 5.4) |
| 데이터 생성 | 시뮬레이션에서 플래너·최적화로 시연을 만들어 학습용 데이터로(MimicGen·MπNets의 방향) |
| 팔 이동이 필요해질 때 | RRT-Connect로 해를 찾고 최적화로 다듬는 5.2절 구성. 구현은 OMPL, cuRobo 등을 참고 |

## 7. 어떤 방법을 쓸지 빠른 가이드 (해석)

| 질문 | 예 | 아니오 |
|---|---|---|
| 좋은 초기 경로가 있나? | 최적화 (또는 warm start) | 샘플링으로 먼저 찾기 |
| 환경이 좁고 복잡한가? | 샘플링, 또는 GCS/IRIS | 최적화 |
| 부드러움·속도·토크 한계가 중요한가? | 최적화 또는 후처리 | 샘플링 + shortcutting이면 충분 |
| 매 주기 다시 계획하나? | 최적화 (MPC, 병렬 시드) | 아무 쪽이나 |
| 같은 환경에서 여러 번 계획하나? | PRM·IRIS+GCS 같은 **미리 계산** | 단일 질의 플래너 |
| 보장(해가 있으면 찾는다)이 필요한가? | 샘플링(확률적), GCS(전역) | 최적화도 가능 |
| 학습 모델이 이미 동작을 내는가? | 안전 필터와 재검사를 붙이기 | 고전 플래너로 시작 |

## 8. 용어

| 용어 | 쉬운 뜻 |
|---|---|
| 단일 질의 / 다중 질의 | 한 번의 시작·목표만 풀기 / 로드맵을 만들어 여러 번 재사용 |
| 터널링 | 점만 검사해서 얇은 장애물을 **건너뛰는** 것 |
| 마진 | 충돌 제약에 두는 여유 거리 |
| 시드 | 최적화의 초기값. 여러 개를 병렬로 돌리면 국소해를 피하기 쉬움 |
| warm start | 이전 해를 다음 최적화의 초기값으로 씀 |
| 다봉(multimodal) 분포 | 정답이 여러 개(위로 돌기, 아래로 돌기)인 분포 |
| 후퇴 지평(receding horizon) | 길게 계획하되 앞부분만 실행하고 다시 계획 |
| MPPI | 제어 열을 샘플링해 비용 가중 평균으로 제어를 정하는 샘플링 기반 MPC |
